# Story 1.4: API Migration - Replace io.ReadWriteCloser with cbio.ReadWriteCloser

## Status
Draft

## Story
**As a** Go developer using the callback-style STOMP client,
**I want** the CallbackConn to use cbio.ReadWriteCloser consistently throughout the API,
**so that** I have a unified interface pattern without the complexity of dual io/cbio adapters and can fully leverage netkit's asynchronous capabilities.

## Acceptance Criteria
1. CallbackConn constructor accepts `cbio.ReadWriteCloser` instead of `io.ReadWriteCloser`
2. Remove `ioAdapter` field from CallbackConn struct
3. Update all frame operations to use `cbio.ReadWriteCloser` directly
4. Update test infrastructure to support cbio interfaces
5. Update example code to use cbio wrapper
6. All existing tests pass with new API
7. Example code compiles and runs successfully
8. No breaking changes to callback functionality

## Dev Notes

### Previous Story Context
From Story 1.1 implementation: The current CallbackConn maintains dual interfaces - `cbio.ReadWriteCloser` for async operations and `io.ReadWriteCloser` as an adapter. This creates unnecessary complexity and inconsistency in the API design.

### Architecture Context
**Source Tree Structure:**
- `callback_conn.go` - Main CallbackConn implementation (lines 16-20: struct definition, line 73: constructor)
- `callback_conn_test.go` - Test infrastructure with FakeConn
- `examples/callback_client_example.go` - Example usage code
- `frame/` package - Frame reading/writing operations (compatible with io.Reader/io.Writer interfaces)

**Frame Package Compatibility:**
- `frame.NewReader(reader io.Reader)` and `frame.NewWriter(writer io.Writer)` accept standard io interfaces
- `cbio.ReadWriteCloser` implements io.Reader and io.Writer interfaces, ensuring full compatibility
- No changes needed to frame package - interface compatibility confirmed

**Current Implementation Details:**
- Constructor currently accepts `io.ReadWriteCloser` and wraps it with `cbio.WrapReadWriteCloser(conn)`
- Struct maintains both `conn cbio.ReadWriteCloser` and `ioAdapter io.ReadWriteCloser`
- Frame operations use `ioAdapter` instead of the primary `conn` field
- This dual-interface pattern creates unnecessary complexity

**API Breaking Change Impact:**
- Constructor signature change requires users to wrap their connections: `cbio.WrapReadWriteCloser(netConn)`
- Test infrastructure needs cbio interface compliance
- Example code needs updating to show proper usage pattern
- No functional changes to callback behavior or STOMP protocol handling

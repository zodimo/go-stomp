# Story 2.2: Implement Frame Routing System

## Status
done

## Story
**As a** Go developer using the callback-style STOMP client,
**I want** a centralized frame routing system that directs incoming frames to appropriate handlers,
**so that** RECEIPT frames reach the correct operations, MESSAGE frames reach subscription handlers, and ERROR frames trigger proper callbacks without race conditions.

## Acceptance Criteria
1. Route RECEIPT frames to pending operations based on receipt-id
2. Route MESSAGE frames to appropriate subscription handlers
3. Route ERROR frames to error callbacks
4. Route CONNECTED frames to connection callbacks
5. Handle unknown/unexpected frames gracefully

### Frame Routing Logic
[Source: Epic technical architecture and existing patterns]

**Frame Routing Algorithm:**
```go
func (r *FrameRouter) routeFrame(f *frame.Frame) {
    switch f.Command {
    case frame.RECEIPT:
        receiptId := f.Header.Get(frame.ReceiptId)
        if op, exists := r.pendingOps[receiptId]; exists {
            op.ResponseCh <- f
            delete(r.pendingOps, receiptId)
        }
    
    case frame.MESSAGE:
        subscriptionId := f.Header.Get(frame.Subscription)
        if sub, exists := r.subscriptions[subscriptionId]; exists {
            // Route to existing handleMessageFrame logic
        }
    
    case frame.ERROR:
        // Route to error callbacks
    
    case frame.CONNECTED:
        // Route to connection callbacks
    
    default:
        // Log unknown frame, handle gracefully
    }
}
```

# Story 1.1: Implement cbio-based connection wrapper and basic STOMP protocol handling

## Status
done

## Story
**As a** Go developer using the STOMP client library,
**I want** a callback-style STOMP client that uses go-netkit cbio interfaces,
**so that** I can implement asynchronous, event-driven STOMP communication alongside the existing synchronous client.

## Acceptance Criteria
1. Add go-netkit@v0.2.0 dependency to go.mod
2. Implement `CallbackConn` struct using cbio interfaces
3. Support CONNECT/CONNECTED frame exchange with callbacks
4. Support DISCONNECT/RECEIPT frame exchange with callbacks
5. Implement protocol version negotiation (1.0, 1.1, 1.2)
6. Add connection state management with event callbacks
7. Create basic error handling with callback mechanisms
8. All existing tests continue to pass

### Existing System Architecture
[Source: Existing codebase analysis]

**Current STOMP Implementation:**
- Synchronous client using `io.ReadWriteCloser` interface
- Frame-based messaging using `github.com/go-stomp/stomp/v3/frame` package
- Support for STOMP protocol versions 1.0, 1.1, 1.2
- Connection management through `Conn` struct in `conn.go`
- Protocol negotiation with version checking via `version.CheckSupported()`
- Heart-beat support with `frame.ParseHeartBeat()` logic
- Receipt handling for reliable messaging
- Channel-based internal communication (readCh, writeCh)

**Key Components to Reuse:**
- `frame` package: Frame parsing, encoding, command constants
- Version negotiation logic from existing `ConnectWithContext` function
- Heart-beat parsing and timeout calculation
- Receipt handling patterns from existing `Disconnect()` method
- Error handling patterns using `Error` struct

**Integration Points:**
- Frame processing will reuse existing `frame.Reader` and `frame.Writer`
- Protocol compliance will leverage existing frame validation
- STOMP specification handling will use existing constants and logic

**CallbackConn Structure (to be implemented):**
```go
type CallbackConn struct {
    // cbio interface for asynchronous I/O
    conn cbio.ReadWriteCloser
    
    // Connection state
    state ConnectionState
    
    // Protocol information (reuse existing types)
    version stomp.Version
    session string
    server string
    
    // Timeouts (reuse existing patterns)
    readTimeout time.Duration
    writeTimeout time.Duration
    
    // Callback handlers
    connectCallback ConnectCallback
    disconnectCallback DisconnectCallback
    stateChangeCallback StateChangeCallback
    errorCallback ErrorCallback
}
```

**Callback Function Types (to be defined):**

# Story 2.3: Operation Synchronization

## Status
Ready for Review

## Story
**As a** Go developer using the callback-style STOMP client,
**I want** all operations to use the centralized frame router instead of individual readers,
**so that** there are no race conditions, operations have proper timeout handling, and the system maintains thread-safe access to all pending operations.

## Acceptance Criteria
1. Replace individual readers with operation registration system
2. Implement timeout handling for pending operations
3. Ensure thread-safe access to pending operations map
4. Clean up expired/completed operations

### Current Frame Router Implementation
[Source: callback_conn.go analysis - lines 15-185]

**Existing Infrastructure:**
```go
type PendingOperation struct {
    Type       string             // "connect", "send", "subscribe", etc.
    ReceiptID  string             // Receipt ID to match
    ResponseCh chan *frame.Frame  // Channel to send response
    ErrorCh    chan error         // Channel to send errors
    Context    context.Context    // For timeout handling
    Cancel     context.CancelFunc // Cancel function
}

type FrameRouter struct {
    pendingOps    map[string]*PendingOperation
    subscriptions map[string]*CallbackSubscription
    mu            sync.RWMutex
    stopCh        chan struct{}
    conn          *CallbackConn
}
```

**Available Methods:**
- `RegisterPendingOperation(op *PendingOperation)` - Thread-safe operation registration
- `UnregisterPendingOperation(receiptID string)` - Thread-safe operation cleanup
- `RouteFrame(f *frame.Frame)` - Routes frames to appropriate handlers
- `Stop()` - Cancels all pending operations and cleans up

### Required Implementation Changes

**1. Operation Registration Pattern (AC: 1)**
Replace this anti-pattern:
```go
// OLD: Individual reader (race condition source)
reader := frame.NewUnwrapCbioReader(c.conn)
go func() {
    for {
        response, err := reader.ReadSync()
        // Handle response...
    }
}()
```

With this pattern:
```go
// NEW: Frame router registration
ctx, cancel := context.WithTimeout(context.Background(), timeout)
defer cancel()

pendingOp := &PendingOperation{
    Type:       "operation_type",
    ReceiptID:  receiptId,
    ResponseCh: make(chan *frame.Frame, 1),
    ErrorCh:    make(chan error, 1),
    Context:    ctx,
    Cancel:     cancel,
}

c.frameRouter.RegisterPendingOperation(pendingOp)
```

**2. Timeout Handling Enhancement (AC: 2)**
Current timeout handling exists but needs enhancement:
- Add timeout monitoring goroutine in frame router
- Implement automatic cleanup of expired operations
- Add configurable timeout values per operation type
- Ensure consistent timeout behavior across all operations

**3. Thread-Safety Verification (AC: 3)**
Current implementation uses `sync.RWMutex` but needs verification:
- All map access is properly mutex-protected
- No race conditions in concurrent scenarios
- Atomic operation registration/unregistration
- Operation ID collision prevention

**4. Operation Cleanup System (AC: 4)**
Current cleanup exists in `Stop()` method but needs enhancement:
- Periodic cleanup of expired operations
- Memory usage monitoring
- Cleanup metrics and logging
- Proper cleanup on connection close
